## 2. Что нужно знать обязательно

### 2.1. ML-часть

#### OCEAN (Big Five)
- 5 черт личности: **O**penness, **C**onscientiousness, **E**xtraversion, **A**greeableness, **N**euroticism
- Каждая нормализована в `[0, 1]` (из Essays Mairesse 2007)
- Порядок в коде: `["cOPN", "cCON", "cEXT", "cAGR", "cNEU"]` — **строго O, C, E, A, N**
- 5 признаков — стандарт психологии личности, хорошо изучен, есть датасет с разметкой

#### Steering Vectors vs LoRA vs Full Fine-tune

| Метод | Trainable params | Модифицирует веса | Интерпретируемость |
|-------|-----------------|-------------------|--------------------|
| Full fine-tune | ~600M | Да | Низкая |
| LoRA (r=8) | ~10⁵–10⁶ | Да (через адаптеры) | Средняя |
| **Steering Vectors** | **5 120** | **Нет (hook)** | **Высокая** |

Steering vectors инжектируются через `register_forward_hook` — backbone не меняется, можно убрать в любой момент.

#### Почему layer 14 (middle-layer hypothesis)
- Ранние слои (0–5): синтаксис, токены
- **Средние слои (~14)**: семантика, концепты — здесь steering наиболее эффективен
- Поздние слои (25–28): предсказание следующего токена
- `target_layer = num_hidden_layers // 2` — **никогда не хардкодим 14**, берём из `model.config`

#### Frozen OCEAN Classifier в loss
- Differentiable proxy для personality-консистентности
- Loss: `L = CE_LM + λ · BCE(OceanClassifier(pooled_last_hidden), target_profile)`
- λ=0.1 — баланс: не даём LM-perplexity деградировать, но steering работает
- Classifier заморожен → не переобучается на steering-сигнал

#### Почему BCE, а не MSE для OCEAN
- Значения нормализованы в `[0, 1]` → трактуются как вероятности
- BCE = бинарная кросс-энтропия, корректна для вероятностных таргетов
- MSE не штрафует за уверенные неправильные предсказания так же сильно

#### Метрики
| Метрика | Что меряет |
|---------|-----------|
| `MAPE_ocean` | Средняя абсолютная процентная ошибка OCEAN-классификатора |
| `Perplexity` | Качество языковой модели (ниже = лучше) |
| `BLEU` | Точность n-gram совпадений с референсом |
| `ROUGE-L` | Длиннейшая общая подпоследовательность с референсом |
| `Distinct-1/2` | Разнообразие ответов (доля уникальных uni/bigrams) |

### 2.2. MLOps-часть

#### Hydra
- Композиция конфигов: `configs/config.yaml` подключает `data/`, `model/`, `train/`
- CLI-overrides: `train.learning_rate=5e-4 train.max_epochs=5`
- Профили: `default.yaml` (полное обучение), `smoke.yaml` (1 эпоха, 3 шага, CPU)
- **Подводный камень**: Hydra меняет `cwd` на run-specific папку → всегда используем `cfg.paths.*`, никогда `./models/`

```yaml
# configs/config.yaml
defaults:
  - data: essays
  - model: qwen
  - train: default
```

#### DVC
- Версионирует данные и модели (не хранит в git)
- `dvc.yaml` — 6 стадий: `download → preprocess → train_ocean_classifier → export_onnx → train_steering → evaluate`
- `dvc.lock` — хеши входов/выходов каждой стадии
- `dvc repro` — пересобирает только изменившиеся стадии (DAG + хеши)
- Локальный remote: `.dvc-storage/` в корне репо (не нужны облачные credentials)

```bash
uv run dvc repro          # полный пайплайн
uv run dvc repro train_steering  # только одна стадия
uv run dvc dag            # визуализация DAG
```

#### MLflow
- Tracking server: SQLite backend (`mlflow.db`) + локальный artifact store (`./mlruns/`)
- Логируется: git SHA, все гиперпараметры, метрики по эпохам
- Запуск: `uv run mlflow server --host 127.0.0.1 --port 8080 --backend-store-uri sqlite:///mlflow.db --default-artifact-root ./mlruns`
- UI: `http://127.0.0.1:8080`

#### PyTorch Lightning
- Разделение: `LightningModule` (модель + loss) / `LightningDataModule` (данные) / `Trainer` (цикл)
- Автоматический checkpointing (`ModelCheckpoint`), early stopping (`EarlyStopping`)
- Переносимость CPU↔GPU без изменения кода модели

#### FastAPI + Pydantic v2
- `GET /health` — 503 если модель не загружена
- `POST /generate` — генерация с OCEAN-профилем
- Валидация: `Field(ge=0.0, le=1.0)` → 422 на out-of-range значения
- `lifespan` context manager для загрузки модели при старте

```python
class GenerateRequest(BaseModel):
    ocean_profile: dict[str, float]  # каждое поле: Field(ge=0.0, le=1.0)
    situation: str
```

#### Docker Compose
- 3 сервиса: `api:8000` (FastAPI), `gradio:7860` (UI), `mlflow:5000` (tracking)
- Изоляция зависимостей, воспроизводимость окружения
- `docker compose up --build` — поднимает всё

#### Pre-commit + ruff
- `pre-commit install` — хуки запускаются на каждый `git commit`
- `ruff check .` — линтинг, `ruff format .` — форматирование
- Отлавливает баги до push, дешевле CI-линтинга

#### pytest
- `tests/unit/` — 33 теста, чистый Python/PyTorch, без скачивания моделей
- `tests/smoke/` — 8 тестов, tiny-random Qwen2 (`hidden_size=64, num_hidden_layers=2`), CPU, < 5 с
- Разделение позволяет запускать unit-тесты в CI без сети

#### uv
- Быстрый пакет-менеджер (Rust), замена pip+venv
- `uv.lock` — детерминированный lock-файл
- `uv pip install -e ".[dev]"` — установка с dev-зависимостями

### 2.3. Архитектурные решения, которые точно спросят

**Почему `hidden_size` и `num_hidden_layers` из `model.config`?**
Хардкод 1024/28 сломается при смене backbone. `model.config.hidden_size` — единственный источник правды. Smoke-тесты используют `hidden_size=64` — если бы был хардкод, тесты бы упали.

**Почему `train-ocean` / `train-steering` через `subprocess`?**
Hydra парсит `sys.argv` при инициализации. Typer тоже использует `sys.argv`. При прямом вызове Hydra-функции из Typer-команды возникает конфликт аргументов. `subprocess` изолирует `sys.argv` каждого процесса.

**Почему user-based split по `#AUTHID`?**
Один автор пишет несколько эссе. Если разбивать по строкам, тексты одного автора попадут и в train, и в test → data leakage → завышенные метрики. User-based split: все тексты одного автора — в одном сплите.

**Почему tiny-random для smoke-тестов?**
`AutoConfig.for_model("qwen2", hidden_size=64, num_hidden_layers=2)` — создаёт модель с random весами без скачивания. CI работает без сети, < 5 с. Реальная Qwen3-0.6B = ~1.2 GB, скачивание в CI неприемлемо.

**Почему λ=0.1?**
Баланс между двумя целями: (1) LM-perplexity не должна сильно расти, (2) steering должен работать. При λ=1.0 модель оптимизирует OCEAN в ущерб связности текста. При λ=0.01 steering почти не влияет. 0.1 — эмпирически найденный баланс.

## 3. Ожидаемые вопросы и заготовленные ответы

**«Почему не LoRA?»**
LoRA добавляет ~10⁵–10⁶ params, модифицирует attention/MLP-веса. Steering vectors — 5 120 params (×100–200 меньше), инжектируются в residual stream через hook, backbone не меняется. Интерпретируемо: каждый из 5 векторов соответствует одной черте OCEAN.

**«Что будет если backbone разморозить?»**
Потеря накопленных знаний (catastrophic forgetting), нестабильность обучения, нужен большой compute. Теряется смысл метода: steering vectors работают именно потому, что backbone стабилен.

**«Почему layer 14?»**
Middle layers содержат семантические представления (middle-layer hypothesis, подтверждена probing-экспериментами). Ранние слои — синтаксис, поздние — token prediction. Steering на layer 14 влияет на смысл, а не на форму.

**«Как воспроизвести эксперимент?»**
```bash
git clone <repo-url>
uv venv --python 3.11 && source .venv/bin/activate
uv pip install -e ".[dev]"
dvc repro
```
Всё детерминировано: `seed=42`, `dvc.lock` фиксирует хеши, `uv.lock` фиксирует зависимости.

**«Что в `dvc.lock`?»**
Хеши (MD5/SHA256) входных файлов, выходных файлов и параметров каждой стадии. `dvc repro` сравнивает текущие хеши с `dvc.lock` и пересобирает только изменившиеся стадии.

**«Чем pre-commit лучше CI-линтинга?»**
Отлавливает проблемы до push — дешевле (не тратим CI-минуты). Разработчик получает фидбек мгновенно, а не через 5 минут ожидания CI.

**«Как масштабировать?»**
Docker Compose → Kubernetes (Helm chart). MLflow local → удалённый сервер (PostgreSQL backend + S3 artifacts). DVC local remote → S3/GCS/Azure. Backbone → более крупная модель (только меняем `BACKBONE_NAME`).

**«Почему Essays Mairesse 2007?»**
Единственный публичный датасет с OCEAN-разметкой на уровне автора (~2 500 авторов, ~2 500 эссе). Альтернативы (myPersonality) закрыты. Нормализация в `[0, 1]` — стандартная для этого датасета.

**«Что такое PersonaChat и зачем он?»**
`bavard/personachat_truecased` — датасет диалогов с персонами. Используется для оценки качества диалогов (BLEU, ROUGE-L, Distinct) — не для обучения. Essays — для обучения OCEAN-классификатора.

**«Почему Sigmoid на выходе OceanClassifierHead?»**
Выходы — 5 независимых вероятностей в `[0, 1]`. Sigmoid применяется поэлементно. Softmax не подходит — черты OCEAN независимы, не конкурируют между собой.

**«Что такое Distinct-1/2?»**
Доля уникальных unigrams (Distinct-1) и bigrams (Distinct-2) среди всех сгенерированных токенов. Низкий Distinct → модель повторяет одни и те же фразы (mode collapse). Distinct > 0.3/0.6 — приемлемо.

**«Зачем ONNX-экспорт?»**
ONNX-формат позволяет запускать OceanClassifierHead без PyTorch (например, в production на C++ inference engine). Также ускоряет inference через ONNX Runtime.

**«Почему uv, а не pip?»**
uv написан на Rust, в 10–100× быстрее pip при установке. `uv.lock` детерминирован (как `poetry.lock`). Поддерживает `pyproject.toml` без дополнительных инструментов.

**«Что логируется в MLflow?»**
Git commit SHA (воспроизводимость), все гиперпараметры из Hydra-конфига, метрики по эпохам (train_loss, val_loss, val_mape_ocean), путь к артефактам (чекпоинты, ONNX).

**«Почему 3 Docker-сервиса, а не 1?»**
Разделение ответственности: API, UI и MLflow — независимые компоненты. Можно масштабировать API отдельно. MLflow можно заменить на внешний сервер без пересборки остальных образов.

| `MAPE_ocean` | < 25% | OCEAN-классификатор адекватен |
| `Perplexity` | baseline + < 10% | Steering не ломает LM |
| `BLEU` | 5–15 | Малая модель, не ChatGPT |
| `ROUGE-L` | 10–20 | Малая модель |
| `Distinct-1` | > 0.3 | Нет коллапса в повторы |
| `Distinct-2` | > 0.6 | Нет коллапса в повторы |

### Шаг 9. Возможные проблемы и решения

| Проблема | Решение |
|----------|---------|
| OOM на T4 | Уменьшить `data.batch_size=8`, добавить `train.accumulate_grad_batches=4` |
| Слишком долго | Уменьшить `train.max_epochs=2`, использовать subset Essays |
| Loss взрывается | Уменьшить `model.lambda_steering=0.05` |
| HF download timeout | `export HF_HUB_ENABLE_HF_TRANSFER=1` |
| CUDA out of memory при export_onnx | Запускать на CPU: `CUDA_VISIBLE_DEVICES="" uv run dvc repro export_onnx` |
