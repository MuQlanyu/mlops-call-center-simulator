Тренажер для сотрудников колл-центров
Мун Павел Юрьевич
Постановка задачи
Сотрудники колл-центров в ходе своей работы сталкиваются с самыми разными клиентами, поэтому вопрос обучения таких сотрудников предполагает общение с людьми с разными ситуациями и разными личностями. Ошибка сотрудника колл-центра влечет большие проблемы для компании. Данный проект предлагает решение в формате текстового бота, которому можно настраивать профиль и ситуацию в которой он оказался. Профиль будет задаваться и оцениваться с помощью OCEAN (Big-5), а ситуация с помощью системного промпта. Если формально, то ставиться задача условной генерации ответов (ситуация \+ профиль)
Формат входных и выходных данных
Вход: история диалога (список строк), ситуация клиента (строка), профиль (5 параметров, скорее всего числа на отрезке \[0, 1\]), реплика сотрудника (строка
Выход: реплика клиента (строка)
Метрики
MAPE_ocean (llm-as-a-judge): \<0.3 (тогда можно будет различать положительное значение и отрицательное значение параметров). Метрика предполагает генерацию диалогов и последующую оценку ответов клиента c помощью сильной модели LLM (скорее всего deepseek, так как бесплатный), а после подсчет MAPE по OCEAN
Валидация и тест
Сплит в соотношении 80|10|10 (train | val | test). Фиксация сплита с помощью сида. Также будет сгенерировано несколько десятков диалогов и проверено качество на них
Датасеты
Pandora ([https://psy.takelab.fer.hr/datasets/all/pandora/](https://psy.takelab.fer.hr/datasets/all/pandora/)) - датасет reddit - комментариев, оттуда нужны комментарии и разметка OCEAN. Проблема: нужно запросить доступ к датасету, не факт, что предоставят. Размер: более 17М комментариев (должно быть больше 10 МБ)
MTHR/OCEAN - датасет фраз с разметкой OCEAN. Проблемы: смещенность разметки OCEAN (уже работал с датасетом), малый размер (около 1000 диалогов)
PersonaChat (https://parl.ai/projects/personachat/) - датасет диалогов. Проблема: нет разметки OCEAN, можно попробовать прогнать через классификаторы OCEAN и получить размеченный датасет. Размер: \>600MB
Моделирование
Бейзлайн
Запромптить небольшую открытую модель, к примеру qwen3-0.6B, то есть в системный промпт положить значение параметров OCEAN \+ ситуации, также к каждому значению дать некоторое описание (можно дискретизировать шкалу и подготовить описания для каждого значения
Основная модель
Qwen3-0.6B /Qwen3-4B (чтобы помещалось в коллаб). Способ дообучения: steering vectors по каждой из осей OCEAN.
Внедрение
Это будет чат-бот, оформленный с помощью библиотеки Gradio (ползунки OCEAN, окно системного промпта, диалоговое окно). Компоненты: Docker compose (для оркестрации), MLFlow (для трекинга)\<Опишите, в каком виде ваша модель будет использоваться (пакет, сервис, чат бот, etc). Нужны ли для этого метода какие-то дополнительные компоненты? Это поможет вам правильно спроектировать работу с моделью\>

Review
Недостатки
Постановка задачи
* Не указано название проекта в требуемом формате (заголовок h1), что является критическим нарушением.
* Отсутствует описание размера входных данных (например, длина диалогов, количество токенов).
* Не приведён конкретный пример входных и выходных данных (ни в тексте, ни по ссылке).
* Указана только одна метрика (MAPE_ocean), что недостаточно для надёжной оценки; требуется минимум 5 метрик.
* Не указаны ожидаемые значения для метрик, кроме MAPE, и отсутствует обоснование (ссылки на статьи/бейзлайны).
* Описание датасетов неполное: не указаны даты публикации, авторы, точный размер на диске (указано только "больше 10 МБ" и ">600MB"), не проведён первичный анализ данных.
* Не указано количество объектов в датасетах (только "более 17М комментариев" для Pandora, но без уточнения, сколько из них пригодны для задачи).
Моделирование
* Бейзлайн описан слишком поверхностно: нет полного пайплайна (предобработка, токенизация, генерация, постобработка), только "запромптить модель".
* Основная модель (Qwen3) и метод steering vectors не описаны детально: нет обоснования выбора, не указаны стадии пайплайна (обучение, валидация, постобработка).
* Не описан процесс дообучения: как именно будут использоваться steering vectors, какие данные для этого нужны, как будет оцениваться сходимость.
Внедрение
* Не указан формат модели (ONNX, TorchScript, checkpoint и т.д.).
* Не указаны ресурсы для инференса (CPU/GPU, память, latency/throughput).
* Описание внедрения слишком общее: только "Gradio + Docker compose + MLFlow", без схемы инференса и деталей оркестрации.
Итоговая оценка
Оценка: 0/10
Краткое обоснование: Отсутствует название проекта в требуемом формате (заголовок h1), что является критическим нарушением, влекущим нулевую оценку. Помимо этого, предложение содержит множество недочётов: недостаточно метрик, неполное описание данных, поверхностный бейзлайн и слабое описание внедрения.
