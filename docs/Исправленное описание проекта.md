# Тренажёр для сотрудников колл-центров

Мун Павел Юрьевич

> **Disclaimer:** Базовая модель Qwen3-0.6B загружается из HuggingFace исключительно для получения предобученных весов (frozen backbone). HuggingFace Trainer не используется. Использование HF для загрузки весов согласовано с преподавателем.

---

## Постановка задачи

- **Сухой остаток:** условная генерация текстовых реплик клиента колл-центра по заданному психологическому профилю (Big-5 / OCEAN) и описанию ситуации. Задача — управляемая языковая генерация с контролем личностных характеристик через обучаемые steering vectors.
- **Решаемая проблема:** обучение операторов колл-центра требует взаимодействия с разнообразными типами клиентов. Реальные тренировки дороги и труднопредсказуемы; ошибка оператора в реальном разговоре влечёт репутационные и финансовые потери для компании.
- **Предлагаемое решение:** текстовый бот, которому задаётся профиль клиента (5 числовых параметров OCEAN) и ситуация (системный промпт). Бот генерирует реплики, стилистически соответствующие заданному профилю, без дообучения весов базовой модели — через learnable steering vectors, вставляемые в активации через forward hook.
- **Бизнес-ценность:** снижение времени онбординга новых операторов за счёт доступного симулятора разнообразных клиентских сценариев; уменьшение стоимости ошибок на этапе обучения (тренировка на боте не несёт репутационных рисков); возможность измерять прогресс оператора через KPI (доля успешно закрытых симулированных обращений).

## Формат входных и выходных данных

**Вход:** JSON-объект с историей диалога, ситуацией и профилем клиента.

```json
{
  "history": [
    {"role": "operator", "text": "Добрый день, чем могу помочь?"}
  ],
  "situation": "Клиент звонит по поводу задержки доставки заказа, раздражён.",
  "ocean_profile": {
    "openness": 0.3,
    "conscientiousness": 0.7,
    "extraversion": 0.2,
    "agreeableness": 0.4,
    "neuroticism": 0.8
  }
}
```

**Выход:** JSON-объект с репликой клиента.

```json
{
  "reply": "Я уже третий раз звоню! Где мой заказ? Вы вообще следите за доставкой?"
}
```

**Ограничения:** максимальная длина истории диалога — 10 реплик (≈ 512 токенов контекста); максимальная длина генерируемой реплики — 128 токенов. Каждое значение OCEAN — вещественное число в отрезке [0, 1].

## Датасеты

### Основной: Essays Dataset (Mairesse et al., 2007)

- **Источник:** [Essays Dataset — Pennebaker & King (1999), разметка Mairesse et al. (2007)](http://farm2.user.srcf.net/research/personality/recognizer.html)
- **Размер:** 2 467 эссе, ~4 МБ текста
- **Разметка:** бинарные метки по каждой из 5 осей OCEAN (выше/ниже медианы), что позволяет обучить OCEAN-классификатор
- **Особенности:** единственный широко используемый публичный датасет с Big-5 разметкой на уровне документа; тексты написаны от первого лица, что близко к разговорному стилю

### Вспомогательный: PersonaChat (Zhang et al., 2018)

- **Источник:** [PersonaChat — ParlAI](https://parl.ai/projects/personachat/)
- **Размер:** > 160 000 реплик, ~164 МБ
- **Назначение:** формат диалогов для валидации BLEU/ROUGE-L; не содержит OCEAN-разметки, используется только для оценки диалогового качества

### Опциональный: Pandora (Gjurković et al., 2021)

- **Источник:** [Pandora — TakeLab](https://psy.takelab.fer.hr/datasets/all/pandora/)
- **Размер:** > 17 млн Reddit-комментариев от ~10 000 пользователей с Big-5 разметкой
- **Статус:** требует запроса доступа; используется как дополнительный источник, если доступ будет предоставлен

### Сплит

Сплит **user-based** 80 / 10 / 10 (train / val / test), seed фиксирован (`seed=42`). Обоснование: user-based разбиение исключает утечку данных одного автора между сплитами — тексты одного человека не попадают одновременно в train и val/test, что обеспечивает честную оценку обобщения на новых пользователей.

## Метрики

| Метрика | Целевое значение | Описание |
|---|---|---|
| `MAPE_ocean` | < 0.25 | Среднее MAPE по 5 осям OCEAN через локальный классификатор; порог обоснован бейзлайном (промпт-инжиниринг ожидаемо даёт MAPE ≈ 0.35–0.40) |
| `MAPE_per_axis` | диагностическая | MAPE отдельно по каждой из 5 осей; позволяет выявить слабые оси |
| `Perplexity` | < 50 | Перплексия на held-out тексте; контролирует деградацию языковой модели |
| `BLEU` / `ROUGE-L` | BLEU > 0.10, ROUGE-L > 0.20 | Соответствие диалоговому стилю на PersonaChat; пороги соответствуют уровню небольших диалоговых моделей |
| `Distinct-1` / `Distinct-2` | Distinct-1 > 0.5, Distinct-2 > 0.7 | Лексическое разнообразие; защита от коллапса генерации в повторяющиеся фразы |

**Основная метрика:** `MAPE_ocean`. Целевой порог < 0.25 позволяет надёжно различать высокое и низкое значение каждой оси (разница > 0.5 при MAPE < 0.25 статистически значима). Порог выведен из ожидаемого результата бейзлайна: промпт-инжиниринг без обучения ожидаемо даёт MAPE ≈ 0.35–0.40 по оценкам на Essays.

## Валидация и тест

- **Сплит:** user-based 80 / 10 / 10, `seed=42`, воспроизводимость через DVC
- **Val:** мониторинг `MAPE_ocean` и `Perplexity` после каждой эпохи; early stopping по `MAPE_ocean` (patience=5)
- **Test:** однократная финальная оценка по всем 5 метрикам после выбора лучшего чекпоинта
- **Воспроизводимость:** фиксированный seed, версионирование данных и чекпоинтов через DVC, логирование git commit id в MLflow

## Моделирование

### Бейзлайн

**Qwen3-0.6B + промпт-инжиниринг (zero-shot / few-shot), без обучения.**

Пайплайн:
1. Загрузка Qwen3-0.6B из HuggingFace (frozen, без градиентов)
2. Формирование системного промпта: значения OCEAN с текстовыми описаниями каждого уровня (дискретизация шкалы на 3 уровня: низкий / средний / высокий) + описание ситуации
3. Few-shot: 2–3 примера реплик в стиле заданного профиля
4. Генерация реплики (greedy / top-p sampling)
5. Оценка сгенерированных реплик локальным OCEAN-классификатором → `MAPE_ocean`

Бейзлайн не требует обучения и служит нижней границей для сравнения.

### Основная модель

**Qwen3-0.6B (frozen backbone) + trainable steering vectors, обучаемые через PyTorch Lightning.**

#### Архитектура

- **Backbone:** Qwen3-0.6B, все веса заморожены (`requires_grad=False`)
- **Steering vectors:** 5 learnable векторов размерности `hidden_size` (по одному на каждую ось OCEAN). Вставляются в активации выбранного среднего слоя трансформера через `register_forward_hook`. При форварде активация модифицируется: `h ← h + Σ_i (ocean_i · v_i)`, где `ocean_i` — целевое значение оси из профиля, `v_i` — соответствующий steering vector
- **OCEAN-классификатор:** небольшая голова (Linear → ReLU → Linear → Sigmoid, 5 выходов), предобученная на Essays dataset заранее; при обучении steering vectors заморожена

#### Функция потерь

```
L = CE_LM + λ · CE(OCEAN_classifier(hidden_states), target_profile)
```

- `CE_LM` — кросс-энтропия языковой модели (авторегрессионная)
- `CE(...)` — кросс-энтропия предсказания OCEAN-классификатора относительно целевого профиля
- `λ` — балансировочный коэффициент (гиперпараметр, по умолчанию 0.1)

#### Обучаемые параметры

Только 5 steering vectors (`5 × hidden_size` параметров, для Qwen3-0.6B: `5 × 1024 = 5 120` параметров). Веса backbone и OCEAN-классификатора не обновляются.

#### Ссылки на метод

Метод основан на работах по activation engineering / activation addition:
- [Subramani et al. (2022) — Extracting Latent Steering Vectors from Pretrained Language Models](https://arxiv.org/abs/2205.05124)
- [Turner et al. (2023) — Activation Addition: Steering Language Models Without Optimization](https://arxiv.org/abs/2308.10248)

## Пайплайн обучения

```
Essays dataset
    │
    ▼
1. Препроцессинг Essays
   (токенизация, user-based split 80/10/10, seed=42)
    │
    ▼
2. Предобучение OCEAN-классификатора
   (Linear head поверх Qwen3-0.6B hidden states → 5 бинарных выходов,
    BCE loss, Adam, ~10 эпох; чекпоинт сохраняется в DVC)
    │
    ▼
3. Формирование training pairs
   (эссе + OCEAN-профиль → пары для обучения steering vectors)
    │
    ▼
4. Обучение steering vectors (PyTorch Lightning)
   - Backbone заморожен, OCEAN-классификатор заморожен
   - Оптимизируются только 5 steering vectors
   - Лосс: CE_LM + λ · CE(OCEAN_classifier, target_profile)
   - Валидация по MAPE_ocean и Perplexity после каждой эпохи
   - Early stopping (patience=5)
    │
    ▼
5. Валидация на PersonaChat
   (BLEU, ROUGE-L, Distinct-1/2)
    │
    ▼
6. Экспорт артефактов
   - steering_vectors.pt → DVC
   - ocean_classifier.onnx → DVC (обязательно, Task 3)
   - Qwen3-0.6B checkpoint (frozen) → DVC
```

## Инфраструктура

| Компонент | Назначение |
|---|---|
| **PyTorch Lightning** | Обучение steering vectors; управление циклом обучения, early stopping, чекпоинтами |

## Внедрение

**Схема инференса:**

```
Gradio UI (ползунки OCEAN + системный промпт + диалоговое окно)
    │  HTTP
    ▼
FastAPI backend
    │
    ▼
Qwen3-0.6B (frozen) + steering vectors (применяются через forward hook)
    │
    ▼
Реплика клиента (строка)
```

**Формат поставки:**

| Артефакт | Описание |
|---|---|
| `qwen3-0.6b/` (HF checkpoint, frozen) | Базовая модель, версионируется в DVC |
| `steering_vectors.pt` | 5 learnable векторов, версионируется в DVC |
| `ocean_classifier.onnx` | OCEAN-классификатор в ONNX (обязательно, Task 3) |

**Требования к инфраструктуре:**
- GPU ≥ 4 ГБ VRAM (для Qwen3-0.6B в fp16); CPU-fallback с int8-квантизацией через `bitsandbytes`
- Latency p95 < 3 сек / реплика (на GPU)
- ONNX-экспорт всего LLM — stretch goal (технически сложен из-за авторегрессии; реализуется при наличии времени)
